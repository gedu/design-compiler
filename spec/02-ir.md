# 02 Intermediate representation

One JSON document per screen. It is the only structure the targets may read: a target that peeks at
HTML is a bug, because it re-couples emission to the input format.

Design rule for the whole schema: **every value is already resolved**. No class names, no custom
properties, no \`calc()\`, no \`inherit\`, no units to interpret. If a value still needs reasoning, it
belongs in the extractor, not in the reader.

~~~json
{
  "schema": "design-ir/1",
  "screen": "HomeScreen",
  "source": "screens/HomeScreen.expanded.html",
  "widthClass": "expanded",
  "viewport": { "width": 1280, "height": 900 },
  "theme": "light",
  "tokens": { "ref": "tokens.json", "sha256": "..." },
  "root": { "...": "Node" },
  "components": [ { "...": "ComponentGroup" } ],
  "diagnostics": [ { "...": "Diagnostic" } ]
}
~~~

## Node

A Node is a DOM element that survived reduction (spec/03 explains reduction).

~~~json
{
  "id": "n:podcast-card",
  "tag": "li",
  "component": "podcast-card",
  "role": "Card",
  "states": ["subscribed"],
  "intent": { "scroll": null, "region": "content", "gridMin": null },
  "box": { "x": 16, "y": 96, "w": 280, "h": 312 },
  "layout": {
    "display": "flex",
    "direction": "column",
    "justify": "flex-start",
    "align": "stretch",
    "gap": 8,
    "padding": { "top": 12, "right": 12, "bottom": 12, "left": 12 },
    "margin":  { "top": 0,  "right": 0, "bottom": 0, "left": 0 },
    "wrap": false
  },
  "size": { "width": 280, "height": 312, "minW": null, "minH": null, "aspect": 1.0 },
  "paint": {
    "background": { "hex": "#F8F3FF", "role": "primaryContainer", "source": "data-token" },
    "foreground": { "hex": "#21005D", "role": "onPrimaryContainer", "source": "computed" },
    "elevation": 2,
    "radius": { "px": 12, "shape": "medium", "corners": null },
    "border": null,
    "opacity": 1.0,
    "overflow": "visible"
  },
  "text": null,
  "icon": null,
  "prop": "title",
  "children": ["n:...", "n:..."],
  "notes": []
}
~~~

### Fields that carry decisions

| Field | Producer | Note |
| --- | --- | --- |
| \`role\` | extractor, from the tag plus component name plus structure | the target component name, resolved once: \`Card\`, \`Text\`, \`Row\`, \`Chip\`, \`Icon\`, \`Divider\`, \`Spacer\`, \`Image\`, \`Box\`, \`Switch\`, \`TextField\`, \`TopAppBar\`, \`LazyColumn\`, \`LazyVerticalGrid\` |
| \`states\` | extractor, from \`data-state\` / \`data-variant\` / sibling markup blocks | becomes the parameter list of the generated component |
| \`paint.background.role\` plus its \`source\` | color resolver; \`source\` is \`data-token\`, \`computed\` or \`unresolved\` | \`unresolved\` means the hex is not in the token file: it is a made-up color and it must be visible in the report, never silently emitted as a literal |
| \`paint.elevation\` | from \`data-elevation\` only | null if absent; never derived from \`box-shadow\` |
| \`paint.radius.shape\` | exact lookup against the shape ladder | null when the value is not on the ladder, which is a diagnostic, and the target emits the raw dp with a comment |
| \`size.aspect\` | from \`aspect-ratio\` | becomes \`Modifier.aspectRatio\`, which survives window resize, unlike \`size\` |
| \`prop\` | from \`data-prop\` | non-null means "this literal becomes a parameter" |

## ComponentGroup

The repetition result, and the reason the IR is worth its schema. The extractor groups nodes by
\`data-component\` value with a matching structural signature.

~~~json
{
  "name": "PodcastCard",
  "instanceCount": 8,
  "signature": "li > [div.cover, div.meta > [h3, p]]",
  "signatureStable": true,
  "params": [
    { "name": "title",       "kotlinType": "String", "tsType": "string", "sample": "Compiled Weekly", "variesAcrossInstances": true },
    { "name": "author",      "kotlinType": "String", "tsType": "string", "sample": "Ada Moreno",      "variesAcrossInstances": true },
    { "name": "subscribed",  "kotlinType": "Boolean","tsType": "boolean","sample": false,             "variesAcrossInstances": true, "fromState": "subscribed" }
  ],
  "callbacks": [
    { "name": "onSubscribeClick", "kotlinType": "() -> Unit", "tsType": "() => void", "evidence": "button[data-action=subscribe]" }
  ],
  "parent": "PodcastGrid",
  "listKind": "grid",
  "instances": ["n:...", "n:..."]
}
~~~

### Grouping rules

| Case | Handling |
| --- | --- |
| Same \`data-component\`, same structural signature | one group; differing literals become parameters |
| Same \`data-component\`, signature differs | group anyway, \`signatureStable: false\`, and every difference becomes a parameter or a conditional; flag it |
| Structural signature identical but no \`data-component\` | candidate group, diagnostic \`component-unlabeled\`; do not invent a name silently, derive it and say so |
| Exactly one instance | a component only if it is a region root or is referenced by \`data-component\`; otherwise inline it into the parent. Emitting a one-off component for every DOM element is how these tools produce unreadable code |
| Two nodes, one nested in the other, same component | flatten. Do not emit a wrapper component that only forwards |

### Callbacks are inferred from controls, never invented

A control (button, toggle, input, clickable row) inside a component yields exactly one callback
parameter, and only with evidence: the element, its \`data-action\` or \`aria-label\`, and its state
key. An element that merely looks tappable yields a diagnostic, not a callback. Wrong callback
names survive into APIs and cost more than a missing one.

## Diagnostic

Shared shape for the validator, the extractor and the emitters.

~~~json
{
  "code": "color-unresolved",
  "severity": "error",
  "node": "n:episode-row",
  "message": "#7A5AF8 is not any role in either scheme",
  "fix": "map it to a role in tokens.json or replace it with tertiary",
  "context": "background on li.episode-row"
}
~~~

Severity decides emission: \`error\` stops the target from writing a file, \`warn\` emits and annotates
the output with a comment carrying the code, \`info\` is report only.

## Versioning

\`schema\` is bumped on any change that alters meaning, including reinterpreting a field. Emitters
assert the major version and refuse anything else. The alternative, quietly ignoring a new field,
is how a converter starts generating code that looks right and is stale.
