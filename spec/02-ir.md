# 02 Intermediate representation

One JSON document per screen. It is the only structure the targets may read: a target that peeks at
HTML is a bug, because it re-couples emission to the input format.

Design rule for the whole schema: **every value is already resolved**. No class names, no custom
properties, no \`calc()\`, no \`inherit\`, no units to interpret. If a value still needs reasoning, it
belongs in the extractor, not in the reader.

~~~json
{
  "schema": "design-ir/1",
  "screen": "HomeScreen",
  "source": "screens/HomeScreen.expanded.html",
  "widthClass": "expanded",
  "viewport": { "width": 1280, "height": 900 },
  "theme": "light",
  "tokens": { "ref": "tokens.json", "sha256": "..." },
  "root": { "...": "Node" },
  "components": [ { "...": "ComponentGroup" } ],
  "diagnostics": [ { "...": "Diagnostic" } ]
}
~~~

## Node

A Node is a DOM element that survived reduction (spec/03 explains reduction).

~~~json
{
  "id": "n:podcast-card",
  "tag": "li",
  "component": "podcast-card",
  "role": "Card",
  "states": ["selected"],
  "intent": { "scroll": null, "region": "content", "gridMin": null },
  "box": { "x": 16, "y": 96, "w": 280, "h": 312 },
  "layout": {
    "display": "flex",
    "direction": "column",
    "justify": "flex-start",
    "align": "stretch",
    "gap": 8,
    "padding": { "top": 12, "right": 12, "bottom": 12, "left": 12 },
    "margin":  { "top": 0,  "right": 0, "bottom": 0, "left": 0 },
    "wrap": false
  },
  "size": { "width": 280, "height": 312, "minW": null, "minH": null, "aspect": 1.0 },
  "paint": {
    "background": { "hex": "#F8F3FF", "role": "primaryContainer", "source": "data-token" },
    "foreground": { "hex": "#21005D", "role": "onPrimaryContainer", "source": "computed" },
    "elevation": 2,
    "radius": { "px": 12, "shape": "medium", "corners": null },
    "border": null,

    "overflow": "visible"
  },
~~~

### Fields that carry decisions

| Field | Producer | Note |
| --- | --- | --- |
| \`role\` | extractor, from the tag plus component name plus structure | the target component name, resolved once: \`Card\`, \`Text\`, \`Column\`, \`Row\`, \`Chip\`, \`Icon\`, \`Divider\`, \`Spacer\`, \`Image\`, \`Box\`, \`Switch\`, \`TextField\`, \`TopAppBar\`, \`LazyColumn\`, \`LazyVerticalGrid\`, \`Button\`, \`IconButton\`, \`IconToggleButton\` |
| \`type\` | type resolver, against the scale in spec/03 | the resolved type role of a text node, \`{ role, source, lineClamp, overflow }\`. \`source\` is \`scale\` or \`closest\`; \`closest\` means the four measured properties matched no role exactly and \`notes\` carries \`type-copy:\` with the deltas. null on a node that holds no text. | 
| \`callback\` | extractor, from the control plus the template text | \`{ name, evidence, state, stateProp, focusable }\` on the ONE node a control is. \`evidence\` is \`data-action\`, \`aria-label\` or \`title\`; without one of those there is no callback and a \`callback-inferred\` diagnostic instead. See "A toggle is a different component" for \`state\` and \`stateProp\`. |
| \`states\` | extractor, from \`data-state\` / \`data-variant\` / sibling markup blocks, plus a clickable SURFACE's resolved boolean | becomes the parameter list of the generated component. For a clickable SURFACE this is ALSO the carrier of the boolean its aria state resolves to (see "A toggle is a different component"); only a name the \`data-props\` schema types \`boolean\` lands here, so a hardcoded aria state adds nothing and a \`data-variant\` with no boolean behind it is a variant, not a parameter. |
| \`paint.background.role\` plus its \`source\` | color resolver; \`source\` is \`data-token\`, \`computed\` or \`unresolved\` | \`unresolved\` means the hex is not in the token file: it is a made-up color and it must be visible in the report, never silently emitted as a literal |
| \`paint.elevation\` | from \`data-elevation\` only | null if absent; never derived from \`box-shadow\` |
| \`paint.radius.shape\` | exact lookup against the shape ladder | null when the value is not on the ladder, which is a diagnostic, and the target emits the raw dp with a comment |
| \`size.aspect\` | from \`aspect-ratio\` | becomes \`Modifier.aspectRatio\`, which survives window resize, unlike \`size\` |
| \`prop\` | from \`data-prop\` | non-null means "this literal becomes a parameter" |

## ComponentGroup

The repetition result, and the reason the IR is worth its schema. The extractor groups nodes by
\`data-component\` value with a matching structural signature.

~~~json
{
  "name": "PodcastCard",
  "instanceCount": 8,
  "signature": "li > [div.cover, div.meta > [h3, p]]",
  "signatureStable": true,
  "params": [
    { "name": "title",       "kotlinType": "String", "tsType": "string", "sample": "Compiled Weekly", "variesAcrossInstances": true },
    { "name": "author",      "kotlinType": "String", "tsType": "string", "sample": "Ada Moreno",      "variesAcrossInstances": true },
    { "name": "subscribed",  "kotlinType": "Boolean","tsType": "boolean","sample": false,             "variesAcrossInstances": true, "fromState": "subscribed" }
  ],
  "callbacks": [
    { "name": "onSubscribeClick", "kotlinType": "() -> Unit", "tsType": "() => void", "evidence": "button[data-action=subscribe]" }
  ],
  "parent": "PodcastGrid",
  "listKind": "grid",
  "instances": ["n:...", "n:..."]
}
~~~

### Grouping rules

| Case | Handling |
| --- | --- |
| Same \`data-component\`, same structural signature | one group; differing literals become parameters |
| Same \`data-component\`, signature differs | group anyway, \`signatureStable: false\`, and every difference becomes a parameter or a conditional; flag it |
| Structural signature identical but no \`data-component\` | candidate group, diagnostic \`component-unlabeled\`; do not invent a name silently, derive it and say so |
| Exactly one instance | a component only if it is a region root or is referenced by \`data-component\`; otherwise inline it into the parent. Emitting a one-off component for every DOM element is how these tools produce unreadable code |
| Two nodes, one nested in the other, same component | flatten. Do not emit a wrapper component that only forwards |

### Callbacks are inferred from controls, never invented

A control (button, toggle, input, clickable row) inside a component yields exactly one callback
parameter, and only with evidence: the element, its \`data-action\` or \`aria-label\`, and its state
key. An element that merely looks tappable yields a diagnostic, not a callback. Wrong callback
names survive into APIs and cost more than a missing one.

### A toggle is a different component than a button

\`state\` carries the accessibility attribute that makes this control on/off: \`aria-pressed\`,
\`aria-checked\` or \`aria-expanded\`. It is read off the live element, so it is a fact and not an
inference. \`stateProp\` then names the boolean that drives it, and it comes from ONE place: the
\`{{ }}\` hole inside that attribute in the template text, for instance \`aria-pressed="{{
subscribed }}"\` yields \`stateProp: "subscribed"\`. The attribute is the live node's; the name lives
only in the source, because the runtime consumes the hole. If the attribute holds a literal instead
of a hole, \`stateProp\` stays null: the design has a hardcoded toggle, and naming a parameter for it
would be inventing a prop the design never declared.

The extractor resolves this, not the target: \`role\` is resolved once by the table above, and a target
that re-decided it per framework would be re-deriving a value the IR exists to settle. The extractor's
rule is **a control that has a \`state\` and a boolean \`stateProp\`** takes the component's
toggle role (\`IconToggleButton\` for an icon-shaped control, \`Switch\` where the design drew one), and **a control with no \`state\`** takes the
plain role (\`IconButton\`, \`Button\`). The same glyph in both shapes is not the same component, and
the plain role on a toggle silently throws away state the design already drew. What the target reads is
therefore only \`role\` plus \`callback.stateProp\`; the Compose rendering of that pair is spec/04's
row, and on every target the boolean \`stateProp\` becomes a parameter of the component.

A clickable **surface** is the exception and keeps its surface role: a \`Card\` that carries
\`role="button"\` and \`aria-pressed\` is still a \`Card\`, because losing the surface loses its color,
shape and elevation. Its boolean is a parameter, not a toggle component, and **the field that carries
it is \`Node.states\`**: the surface's \`states\` gains the prop name the template's hole resolved to
(\`aria-pressed="{{ selected }}"\` -> \`states: ["selected"]\`). It cannot ride \`callback\`, because a
surface legitimately has no accessible name to name a callback from, and inventing one is forbidden
above. The \`callback-inferred\` diagnostic such a card raises names the missing NAME and says nothing
about this boolean, which is why the boolean needs a field of its own; \`states\` is already this
schema's "the design drew a state" field, so no field is invented. Measured on a mutated copy that gives
the card an \`aria-label\`, the same boolean arrives in \`callback.stateProp\` and \`states\` stays empty
-- ONE fact with two carriers, depending on whether the surface can be named. A target must therefore
bind a surface boolean from whichever field holds it; reading only one of the two emits a parameter
nothing consumes. Which target modifier a surface
boolean becomes is NOT recorded here: \`states\` stays target-neutral and each mapping decides that
once (spec/04's \`Card\` row for Compose).

Measured on the annotated fixture, where this rule came from: **two** nodes in the frame carry
\`aria-pressed\`, the card root and the subscribe button, so the attribute by itself does not make a
toggle component. The button is the one that is an actual \`button\` element with an accessible name,
the template drives its attribute with \`{{ subscribed }}\`, and the \`data-props\` schema declares
\`subscribed\` as \`tsType: "boolean"\` with default \`false\`. The card root is driven by
\`{{ selected }}\` and stays a \`Card\` under the exception above, its boolean reaching \`states\` and not \`callback\`. The hand-written
reference card,
given the same design, writes \`IconToggleButton(checked = subscribed, onCheckedChange =\`
\`{ onSubscribeClick() })\` here and a plain \`IconButton\` in its search field, which is the
distinction this rule encodes rather than a preference of ours.

## Diagnostic

Shared shape for the validator, the extractor and the emitters.

~~~json
{
  "code": "color-unresolved",
  "severity": "error",
  "node": "n:episode-row",
  "message": "#7A5AF8 is not any role in either scheme",
  "fix": "map it to a role in tokens.json or replace it with tertiary",
  "context": "background on li.episode-row"
}
~~~

Severity decides emission: \`error\` stops the target from writing a file, \`warn\` emits and annotates
the output with a comment carrying the code, \`info\` is report only.

## Versioning

\`schema\` is bumped on any change that alters meaning, including reinterpreting a field. Emitters
assert the major version and refuse anything else. The alternative, quietly ignoring a new field,
is how a converter starts generating code that looks right and is stale.
